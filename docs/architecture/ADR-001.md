# ADR-001: Arquitectura Desacoplada Enterprise para LogiClear AI

**Fecha:** 2026-10-09  
**Estado:** APROBADO  
**Autor:** @architecture_master (Principal Software Architect)  
**Proyecto:** LogiClear AI — Plataforma B2B Enterprise SaaS  
**Versión:** 1.0.0  

---

## 1. Contexto y Problema

Las empresas importadoras y operadores logísticos gestionan expedientes aduaneros compuestos por múltiples documentos no estructurados y estructurados:
1. Facturas Comerciales Internacionales (origen en múltiples divisas, incoterms CIF, FOB, CFR, EXW).
2. Conocimientos de Embarque Marítimo (Bill of Lading - BL / AWB).
3. Declaración Aduanera de Mercancías (DUA / DAM aduanera).
4. Liquidaciones de tributos aduaneros (Ad-Valorem, Impuesto General a las Ventas - IGV, Impuesto de Promoción Municipal - IPM, Percepciones).
5. Comprobantes de gastos de flete local, almacenamiento y agenciamiento de aduana.

Actualmente, el proceso de cotejo entre lo declarado ante la autoridad tributaria y lo facturado por el proveedor en origen es manual, propenso a errores de redondeo, discrepancias arancelarias (HS Codes erróneos) y sobrecostos por asignación inexacta de Landed Cost (costo total puesto en almacén).

Se requiere una arquitectura desacoplada, multi-tenant hermética, con rendimiento de sub-segundo para consultas analíticas y procesamiento asíncrono para ingesta OCR/LLM y conciliación matemática determinista.

---

## 2. Decisión de Arquitectura

Se aprueba formalmente la adopción de un modelo **Clean Architecture & Modular Monolith** con desacoplamiento estricto por capas y aislamiento multi-tenant mediante **PostgreSQL Row Level Security (RLS)** y Next.js 15 App Router:

### A. Capas del Sistema (Dependency Rule)
1. **Dominio Central (Pure Domain / Core Engine):**
   - Entidades puras y funciones matemáticas deterministas sin dependencias de frameworks ni I/O.
   - Cálculo de factores de prorrateo (peso neto vs. valor FOB), liquidación de aranceles y auditoría de discrepancias.
2. **Capa de Aplicación (Use Cases & Orchestration):**
   - Casos de uso de importación de expedientes, disparo de cotejos, validación de tolerancias y gestión de suscripciones.
   - Interfaces (Ports) para repositorios de persistencia, agentes LLM y pasarelas de pago.
3. **Capa de Infraestructura (Adapters & External Drivers):**
   - Persistencia: PostgreSQL con RLS enforced por sesión transaccional (`app.current_tenant_id`).
   - LLM Extraction Engine: Pipeline multimodal con Zod Schemas y temperatura 0.0.
   - Billing: Stripe Webhook Adapter con validación HMAC e idempotencia transaccional.
4. **Capa de Presentación (Next.js 15 App Router & API Endpoints):**
   - Server Components para streaming seguro de datos y Client Components reactivos para visualización comparativa 1:1, drag-and-drop y matrices de semáforos de tolerancia.

## 3. Justificación de Alternativas Descartadas

| Alternativa Evaluada | Razón de Descarte |
| :--- | :--- |
| **Microservicios distribuidos iniciales** | Complejidad operacional excesiva, latencia de red en reconciliaciones transaccionales y riesgo de split-brain en el ledger de auditoría aduanera. |
| **Separación de bases de datos por tenant (Database-per-tenant)** | Costo prohibitivo de infraestructura para el tier Starter (\$99/mo), sobrecarga en migraciones de esquema y problemas de conexión pooling. |
| **Autenticación sin RLS a nivel de aplicación** | Riesgo crítico de fuga de datos (Data Leak / BOLA) ante bugs en cláusulas WHERE; RLS garantiza aislamiento a nivel kernel de PostgreSQL. |
| **LLMs evaluando cálculos numéricos en texto** | Inaceptable: LLMs no son calculadoras deterministas. La extracción se desacopla completamente del cálculo matemático. |

---

## 4. Consecuencias Técnicas

### Positivas
- **Aislamiento Criptográfico y Relacional:** Las políticas de RLS garantizan que ninguna query devuelva datos de otro tenant, incluso ante fallos de sanitización en el backend.
- **Determinismo Matemático:** 100% de reproducibilidad en el Landed Cost mediante aritmética de coma fija / BigInt / Decimal cents.
- **Cero Acoplamiento:** Los motores de extracción multimodal y de pagos son adaptadores reemplazables sin tocar la lógica de conciliación.
- **Auditoría Continua:** Cada expediente posee un hash SHA-256 inmutable de su conciliación.

### Desafíos y Mitigaciones
- **Connection Pooling con RLS:** Exige establecer `SET LOCAL app.current_tenant_id = :tenant_id` al inicio de cada transacción del pool.
- **Coste de LLM Token Ingestion:** Se implementa validación Zod estricta previa a la persistencia para descartar extracciones fallidas sin reprocesamiento innecesario.

---

## 5. Fitness Functions y Conformidad

- **ArchUnit / Dependency Cruiser:** El dominio central no debe importar `@/lib/db`, `next`, ni librerías de terceros excepto utilitarios de matemáticas o esquemas puros.
- **Latencia de Conciliación:** 1,000 partidas arancelarias deben liquidarse en menos de 25 milisegundos en memoria.
- **Multi-Tenant Leak Test:** 0% de fuga de datos en suites de penetración con tenants cruzados.
